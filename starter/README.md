# Аудитории клубов: MCP-сервер

[Условие и шкала](../README.md) · [Сдача](../README.md#сдача)

## 1. Вызовите `ping` на своем компьютере

Запустите готовый [сервер](server.py) в одном терминале, а из другого отправляйте ему запросы с помощью `curl`. Нужны [Python 3.14](https://www.python.org/downloads/), `curl` и оболочка Bash или Zsh (на Windows подойдёт Bash в WSL). Docker, учебная ВМ и LLM не нужны

Здесь `curl` играет роль MCP-клиента. Сначала клиент и сервер договариваются о версии протокола. Затем клиент узнает имена инструментов и их аргументы. Только `tools/call` запускает функцию

**Терминал 1.** Если у вас еще нет копии репозитория, скачайте ее и перейдите в корень проекта:

```bash
git clone https://github.com/Nikfilk2030/mcp_server.git
cd mcp_server
```

Из корня проекта запустите сервер:

```bash
cd starter
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --host 127.0.0.1 --port 8000
```

Если команда `python3.14` не найдена, проверьте `python3 --version`: если это 3.14.x, используйте `python3` в команде создания окружения. Дождитесь строки `Uvicorn running on http://127.0.0.1:8000` и оставьте терминал открытым

**Терминал 2: составьте свои запросы.** Сервер принимает JSON-RPC 2.0 через HTTP POST на `http://127.0.0.1:8000/mcp`. Для каждого шага напишите свою команду `curl`. У запроса есть `id`: сервер повторяет его в JSON-ответе, чтобы тот можно было сопоставить с запросом. Уведомление отправляют без `id`: HTTP-статус подтверждает прием, но JSON-ответа не будет

| Шаг | Что выяснить или сделать |
|---|---|
| `initialize` | Представьтесь как клиент и предложите версию протокола `2025-11-25`. Какую версию вернул сервер? |
| `notifications/initialized` | Сообщите, что клиент готов. Здесь нормальный ответ сервера: HTTP 202 без тела |
| `tools/list` | Узнайте, какие инструменты доступны. Найдите `ping` и посмотрите в его `inputSchema`, нужны ли аргументы |
| `tools/call` | Используйте сведения из предыдущего ответа, чтобы вызвать инструмент. Найдите `pong` в результате вызова |

Формат сообщений ищите в разделах [инициализация клиента](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [заголовки HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) и [инструменты](https://modelcontextprotocol.io/specification/2025-11-25/server/tools). В [справочнике curl](https://curl.se/docs/manpage.html) пригодятся `--data` для тела запроса, `--header` для заголовков и `--include`, чтобы увидеть HTTP-статус. Если сервер отклоняет сообщение, сверьте `Content-Type` и `Accept` с документацией по транспорту. После инициализации передавайте согласованную версию в `MCP-Protocol-Version`

Сохраните команды и ответы в [отчет](../report.md), затем остановите сервер через `Ctrl+C` в первом терминале

## 2. Добавьте поиск и проверьте его локально

В [tools.py](tools.py) список `SCHEDULE` уже прочитан из [schedule.json](schedule.json). Реализуйте `lookup_club_room(club_id)`: верните поле `room` для точного совпадения `club_id`. Если такой записи нет, верните строку `Клуб не найден`, а не исключение. Зарегистрируйте инструмент в [server.py](server.py) рядом с `ping`

Из каталога `starter` запустите тесты:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

До реализации поиска ожидается `NotImplementedError`, тест `ping` уже проходит. После реализации должны пройти все тесты. Они вызывают функции напрямую и не проверяют регистрацию: снова запустите сервер, повторите обмен из первого шага и найдите в `tools/list` **оба** инструмента. Вызовите поиск с `orbit` и `ORBIT`. Ожидаются `Б-204` и `Клуб не найден` соответственно, оба без ошибки инструмента

## 3. Запустите тот же сервер на учебной ВМ

1. Скопируйте [Dockerfile.example](Dockerfile.example) в `starter/Dockerfile` и заполните `TODO` по [справочнику Dockerfile](https://docs.docker.com/reference/dockerfile/). Передайте код, данные и Dockerfile на ВМ. Из каталога `starter` на ВМ [соберите образ](https://docs.docker.com/reference/cli/docker/buildx/build/) и [запустите контейнер](https://docs.docker.com/reference/cli/docker/container/run/). Compose необязателен
2. Внутри контейнера сервер должен слушать `0.0.0.0:8000`. Порт контейнера [привяжите только к `127.0.0.1:8000` ВМ](https://docs.docker.com/engine/network/port-publishing/). Открывать порт MCP в интернет не нужно
3. В одном терминале на ВМ покажите `docker ps`, затем повторите свой обмен через `curl`: проверьте список инструментов и результат поиска. Теперь `127.0.0.1` в команде означает ВМ, а не ноутбук. Если будете подключать ассистента, пока не останавливайте контейнер

## 4. Задайте вопрос ассистенту

Можно взять любой ассистент с поддержкой MCP, в котором видно аргументы и результат вызова. Для локального клиента оставьте контейнер на ВМ запущенным. На **ноутбуке** выполните:

```bash
ssh -N -L 127.0.0.1:18000:127.0.0.1:8000 user@VM_IP
```

Замените `user@VM_IP` на свой SSH-адрес. Пока эта команда работает, запросы к порту `18000` ноутбука попадают на порт `8000` ВМ. Например, в локальном [VS Code с поддержкой MCP](https://code.visualstudio.com/docs/copilot/customization/mcp-servers) выберите `MCP: Add Server`, тип `HTTP`, адрес `http://127.0.0.1:18000/mcp`. В чате режима Agent включите инструмент. Для чата нужен доступ к модели

Спросите про клуб по его идентификатору, не называя функцию. В диалоге раскройте запись вызова и сохраните имя инструмента, аргументы, результат и ответ ассистента. Если клиент показывает только ответ, приложите связанный с этим диалогом журнал вызовов клиента

Облачный клиент не видит `127.0.0.1` ноутбука. Если используете учебного ассистента, см. [информацию о доступе](../README.md#сдача). Вместо него можно воспользоваться локальным клиентом через SSH

После демонстрации закройте SSH-туннель через `Ctrl+C`. На ВМ остановите свой контейнер командой `docker stop <имя-контейнера>`. Сохраните отчет и код, затем проверьте в облачной консоли, не продолжается ли оплата ВМ, диска или публичного IP
