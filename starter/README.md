# Аудитории клубов: MCP-сервер

## 4 балла: запустить готовый пример

Из корня репозитория выполните:

```bash
python3 starter/demo.py
```

Пример вызывает готовую функцию `ping` и печатает `pong`. Приложите команду и её вывод. Это локальный вызов без сетевого транспорта: устанавливать зависимости, запускать сервер и писать запросы не нужно

## 6 баллов: найти аудиторию через MCP на ВМ

Здесь начинается полный обмен по MCP. Клиент (`curl`) отправляет запрос на `/mcp`, [server.py](server.py) выбирает зарегистрированный инструмент, а функция из [tools.py](tools.py) возвращает результат. В заготовке зарегистрирован только `ping`

Реализуйте в `tools.py` инструмент `lookup_club_room(club_id: str)` и зарегистрируйте его в `server.py` рядом с `ping`. Ищите точное совпадение `club_id` в [schedule.json](schedule.json) и возвращайте строку `room` из найденной записи. Если клуба нет, верните `Клуб не найден` как обычный результат, без исключения. Например, `orbit` и `ORBIT` различаются

**Для локальной отладки** запустите из каталога `starter`:

```bash
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python server.py
```

Тесты вызывают функции напрямую и не проверяют регистрацию. Для сдачи проверьте сервер через сеть на учебной ВМ:

1. Скопируйте [Dockerfile.example](Dockerfile.example) в `Dockerfile` и допишите инструкции в местах с `TODO` по [справочнику Dockerfile](https://docs.docker.com/reference/dockerfile/): в образе понадобятся Python, зависимости, код и расписание. На учебной ВМ [соберите образ](https://docs.docker.com/reference/cli/docker/buildx/build/) и [запустите контейнер](https://docs.docker.com/reference/cli/docker/container/run/). Внутри контейнера сервер должен слушать `0.0.0.0:8000`, а порт на ВМ [опубликуйте только на `127.0.0.1`](https://docs.docker.com/engine/network/port-publishing/). [Compose](https://docs.docker.com/compose/) необязателен
2. Из терминала **ВМ** своими командами `curl` начните обмен с контейнером, получите `tools/list` и вызовите свой инструмент для известного и отсутствующего клуба. В отчёте покажите команды сборки и запуска, вывод `docker ps`, запросы и ответы. В списке должны быть оба инструмента, для `orbit` ожидается `Б-204`, для `ORBIT` ожидается `Клуб не найден`. Оба вызова должны завершиться без `isError: true`

**Как построить обмен.** Самостоятельно составьте команды `curl` для `POST http://127.0.0.1:8000/mcp` в таком порядке:

| Сообщение | Что проверить в ответе |
| --- | --- |
| `initialize` | Сервер согласовал версию протокола `2025-11-25` и объявил поддержку инструментов |
| `notifications/initialized` | Клиент подтвердил готовность. У уведомления нет `id`, ответ сервера: HTTP 202 без тела |
| `tools/list` | В списке есть `ping` и `lookup_club_room`, из его `inputSchema` видно, какие аргументы нужны |
| `tools/call` | В ответе на каждый вызов поиска есть текстовый результат, а не ошибка инструмента |

Каждое сообщение отправляйте отдельно в формате JSON-RPC 2.0. Для POST укажите `Content-Type: application/json` и `Accept: application/json, text/event-stream`. После `initialize` передавайте согласованную версию в заголовке `MCP-Protocol-Version`. Сервер не хранит сессии, поэтому `Mcp-Session-Id` не нужен

Формат сообщений: [начало работы клиента](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [HTTP и заголовки](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [список и вызов инструментов](https://modelcontextprotocol.io/specification/2025-11-25/server/tools). Для отчёта сохраните свои команды и фактические ответы, включая статус уведомления и оба результата поиска

## 8 и 10 баллов: подключить ассистента и проверить его ответы

Для 8 баллов добавьте свой инструмент или содержательно расширьте поиск, как описано в [условиях задания](../README.md). Укажите, кому он нужен, его параметры и пример результата. Задайте ассистенту обычный вопрос без имени инструмента. Сохраните настройки без секретов и диалог, в котором видны вопрос, выбранный инструмент, аргументы, результат вызова и ответ модели

**Вариант подключения с ноутбука:** оставьте контейнер запущенным на ВМ. На ноутбуке выполните `ssh -N -L 127.0.0.1:18000:127.0.0.1:8000 user@VM_IP`, заменив `user@VM_IP` на адрес для входа по SSH. Пока SSH открыт, порт `18000` ноутбука ведёт на порт `8000` ВМ. Например, в локальном [VS Code с поддержкой MCP](https://code.visualstudio.com/docs/copilot/customization/mcp-servers) выберите `MCP: Add Server` в палитре команд, тип `HTTP` и адрес `http://127.0.0.1:18000/mcp`. В чате в режиме Agent включите инструмент в списке доступных

Облачный MCP-клиент не видит `127.0.0.1` вашего ноутбука: для него это его собственная машина. SSH-подключение не делает сервер публичным. Для облачного клиента нужен разрешённый HTTPS-адрес, доступный из его сети, и поддерживаемая им авторизация. Уточните эти параметры у преподавателя, не публикуйте ключи

Для 10 баллов проведите [проверку на десяти запросах](../assignment/EVAL.md) на том же инструменте и заполните [таблицу результатов](../assignment/eval.csv)
