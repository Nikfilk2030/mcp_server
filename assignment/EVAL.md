# Мини-проверка: когда нужен вызов инструмента?

Возьмите [пустую таблицу](eval.csv). Одна строка соответствует одному запросу и первому ответу модели. Автоматизация и вторая модель для выставления баллов не нужны

## До запуска

Запишите версию расписания (или приложите его копию), название модели, хост, доступные инструменты и настройки. Оставьте включённым только проверяемый инструмент. Если проверяете другой свой MCP, замените клубы и аудитории объектами из своей задачи

Заполните первые пять столбцов для всех десяти строк заранее. В `Запрос` внесите точный текст для модели, в `Эталон` запишите проверяемый ответ или действие, в `Основание` укажите, чем модель должна его обосновать, в `Бюджет` запишите допустимое число вызовов. Подберите:

- 4 запроса о существующих встречах с разными формулировками: эталон берите из расписания, основание должно прийти из результата поиска, бюджет 1
- 2 запроса о встречах, которых в расписании нет: нужен ответ «не найдено» по результату поиска, бюджет 1
- 2 неоднозначных запроса: например, клуб встречается по вторникам и пятницам в разных комнатах. Если без дня поиск невозможен, ожидайте вопрос «В какой день?» без вызова (бюджет 0). Если инструмент возвращает оба варианта, можно заранее выбрать другой эталон: перечислить оба с днями (бюджет 1)
- 2 запроса, где поиск не нужен: например, «Сократи объявление: “Занятие киноклуба пройдёт в аудитории 214”». Эталон: короткое объявление с тем же клубом и номером, основание уже есть в запросе, бюджет 0

## Во время запуска

Для каждой строки откройте новый пустой чат, отправьте только `Запрос` и остановитесь после первого ответа модели пользователю, даже если это уточняющий вопрос. Не выбирайте лучший ответ из нескольких. Скопируйте `Ответ` и укажите в `Запись` файл или метку фрагмента журнала, где целиком виден ход этой попытки, включая аргументы и результаты инструментов. Для случая без вызовов сохраните весь ход от запроса до ответа. В `Вызовы` внесите число фактических вызовов инструмента, включая ошибки и повторы, но не обнаружение инструментов хостом. При сбое сохраните сообщение об ошибке вместо ответа

## Как выставить три независимые оценки

| Столбец | Когда ставить 1 (иначе 0) |
|---|---|
| Цель | Итоговый ответ совпадает с эталоном по смыслу, включая нужное уточнение, если именно оно было целью |
| Опора | Запись показывает требуемое основание: для поиска верны аргументы и результат подтверждает ответ, для ответа без поиска достаточно исходного текста или видимой в нём нехватки сведений. Неподтверждённых фактов в ответе нет |
| Экономность | Число фактических вызовов не превышает заранее заданный бюджет |

Угаданный номер может дать балл за цель, но не за опору. Отсутствие вызова укладывается в бюджет, но само по себе не означает, что задача решена. Если попытка завершилась без ответа, цель и опора равны 0, вызовы считайте как обычно. Если журнал не сохранился, отметьте это явно: не подставляйте ноль вместо неизвестного числа вызовов, поставьте 0 за опору и экономность

### Одна вымышленная строка для разбора, не результат запуска

| ID | Запрос | Эталон | Основание | Бюджет | Ответ | Запись | Вызовы | Цель | Опора | Экономность |
|---|---|---|---|---:|---|---|---:|---:|---:|---:|
| Учебный | Где шахматы в среду? | Аудитория 312 | Результат поиска для шахмат на среду | 1 | В аудитории 312 | Условный ход: два одинаковых запроса «шахматы, среда», оба вернули 312 | 2 | 1 | 1 | 0 |

Номер верный и подтверждён уже первым вызовом. Второй не меняет ни ответ, ни его обоснование, но превышает бюджет. Не переносите эту строку в свою таблицу

## Что написать в выводе

Сложите единицы отдельно по каждому из трёх столбцов и приведите три результата из 10. По одному ID объясните расхождение оценок или, если расхождений не было, покажите, что именно подтвердило ответ. Предложите одно изменение описания инструмента или запроса, которое стоило бы проверить дальше. Эти три суммы описывают поведение модели, а не оценку за ДЗ
