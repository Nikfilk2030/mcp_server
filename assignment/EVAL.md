# Когда модели нужен инструмент?

Проверьте инструмент с уровня на 8 баллов на десяти запросах. Работайте в копии [шаблона CSV](eval.csv): один ID на один запрос, названия столбцов не меняйте

## 1. Подготовьте запросы до запуска

Укажите модель, хост, настройки и версию или копию тестовых данных. Оставьте включённым только проверяемый инструмент. Для каждого ID запишите точный `Запрос`, ожидаемый ответ или действие (`Эталон`), чем его можно подтвердить (`Основание`) и сколько вызовов допустимо (`Бюджет`)

Составьте четыре группы. Примеры ниже относятся к расписанию, для другого инструмента подберите случаи из своей задачи

- **4 поиска с результатом**, бюджет 1. По-разному спросите о данных, которые есть в расписании. Эталон возьмите из файла, а модель должна получить ответ из результата вызова
- **2 поиска без результата**, бюджет 1. Например, укажите конкретный `club_id`, которого нет в файле. Ожидайте «не найдено» по результату поиска
- **2 запроса с недостающими сведениями**. Например, «В какой аудитории встречается мой клуб?» В новом чате клуб не указан: ожидайте уточнения без вызова, бюджет 0. Если ваш инструмент позволяет вернуть все подходящие варианты, можно заранее выбрать их перечисление, бюджет 1
- **2 задачи без поиска**, бюджет 0. Например, попросите сократить объявление, в котором уже указаны клуб и аудитория. В эталоне отметьте, какие сведения надо сохранить

## 2. Сохраните первую попытку

Для каждого ID откройте пустой чат и отправьте только `Запрос`. Остановитесь на первом ответе, даже если модель задала вопрос. Не заменяйте неудачную попытку повтором

- `Ответ`: скопируйте ответ модели. Если ответа не было, запишите ошибку хоста или отметьте отсутствие ответа
- `Запись`: укажите файл или метку в журнале, где виден весь ход от запроса до ответа или сбоя. Раскройте аргументы и результаты вызовов. Для подтверждения нуля вызовов нужен весь ход, а не только текст ответа
- `Вызовы`: посчитайте все попытки вызова инструмента, включая ошибки и повторы. Получение списка инструментов хостом не считайте

## 3. Оцените и объясните результат

В каждой строке поставьте три независимые оценки, по 1 за выполненное условие, иначе 0

- `Цель`: ответ по смыслу совпадает с эталоном. Уточнение тоже считается, если его ожидали
- `Опора`: запись подтверждает ответ. При поиске проверьте аргументы и результат, без поиска проверьте ответ по исходному тексту. В ответе нет неподтверждённых фактов
- `Экономность`: число вызовов не превышает бюджет. Например, два одинаковых поиска при бюджете 1 дают здесь 0, даже если аудитория верна и подтверждена

**Сбой модели или инструмента** при сохранённой записи остаётся результатом эксперимента. Если модель не ответила, цель и опора равны 0, экономность оцените по фактическим вызовам

**Потеря записи** означает, что ход попытки нельзя проверить. В `Запись` укажите «утеряна», в `Вызовы` поставьте «неизвестно», а не 0. За опору и экономность поставьте 0, цель оцените по сохранённому ответу. Не выдавайте потерянную запись за подтверждённую попытку

В выводе приведите три суммы из 10. Разберите один ID: почему оценки разошлись или чем подтверждены, если расхождений нет. Предложите одно изменение запроса или описания инструмента для следующей проверки. Оценивается качество эксперимента, а не число удачных ответов модели
