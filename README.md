# Новые способности Алисы

**Лабораторная работа по Python и Model Context Protocol.**

Сначала вы реализуете два инструмента по точному контракту и пройдёте автоматические тесты. Затем сможете придумать собственную способность Алисы и принять участие в конкурсе MCP-серверов. Результат работы нужно показать в записи демонстрации через учебный harness Алисы.

| Обязательная часть | Свободная часть |
| --- | --- |
| `inspect_unicode`: структурированные данные | Собственная идея, один или несколько инструментов |
| `render_identicon`: изображение PNG | Конкурс после прохождения обязательных тестов |
| Документация MCP, тесты и демонстрация | Отдельные номинации; участие добровольное |

> **Без LLM при разработке.** Нельзя использовать генеративные помощники для кода, отладки, объяснения документации и отчёта. Алиса разрешена только как клиент вашего сервера для проверки интеграции и демонстрации. Полные правила — в [условии](docs/assignment.md#правила-работы).

## Маршрут

1. Прочитайте [условие и критерии оценивания](docs/assignment.md).
2. Запустите шаблон по инструкции ниже.
3. Пройдите [маршрут по документации](docs/reading.md).
4. Реализуйте [контракты двух инструментов](docs/contracts.md) в `tools.py`.
5. Добейтесь прохождения полного набора тестов.
6. [Опубликуйте сервер](docs/deployment.md) и [подключите его к Алисе](docs/alice.md).
7. Подготовьте [сдачу и видео](docs/submission.md). По желанию участвуйте в [конкурсе](docs/contest.md).

## Быстрый старт

Нужны **Python 3.12** и Git. MCP SDK зафиксирован на **2.3.0**. Инструкции для старого `FastMCP` из SDK v1 не соответствуют этому шаблону: здесь используется `MCPServer`.

Создайте свой репозиторий из шаблона, если преподаватель включил **Use this template**, либо сделайте fork. Клонируйте свою копию и перейдите в её каталог.

Linux / macOS:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -m starter
python server.py
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pytest -m starter
python server.py
```

Если политика PowerShell не разрешает активацию, вызывайте `.\.venv\Scripts\python.exe` вместо `python`; менять системную политику не требуется.

Сервер работает на `http://127.0.0.1:8000/mcp`. Во втором терминале с активированным окружением:

```bash
python client.py
python client.py --tool echo --arguments '{"text":"Привет, Алиса!"}'
```

В PowerShell при проблемах с кавычками используйте `python --% client.py --tool echo --arguments "{\"text\":\"hello\"}"`.

`client.py` — обычный MCP-клиент без LLM. Он показывает список инструментов и позволяет вызывать их напрямую. `/healthz` проверяет доступность процесса; это не MCP endpoint.

## Проверки

```bash
python -m pytest -m starter
python -m pytest -m assignment
python -m pytest
python -m ruff check .
```

**В исходном шаблоне проходят только тесты `starter`.** Обязательные инструменты намеренно не реализованы: тесты `assignment` и полный запуск должны падать с сообщением о необходимости регистрации инструментов. Это не неисправность установки.

CI **Template checks** проверяет каркас и стиль. Он не означает, что задание решено. В своей копии откройте **Actions → Assignment checks → Run workflow** и выберите ветку решения: этот workflow запускает все тесты. Для автоматической проверки решения при каждом push можно создать repository variable `RUN_ASSIGNMENT_TESTS` со значением `true`.

Тесты сами поднимают и останавливают сервер на свободном локальном порту. Внешний сервер проверяется так:

```bash
MCP_TEST_URL=https://your-host.example/mcp python -m pytest
```

В PowerShell задайте `$env:MCP_TEST_URL="https://your-host.example/mcp"`, затем выполните `python -m pytest`.

## Файлы

| Путь | Назначение |
| --- | --- |
| `server.py` | Транспорт, запуск, `echo`, проверка доступности |
| `tools.py` | Ваши обязательные инструменты |
| `custom_tools.py` | Инструменты для конкурса |
| `client.py` | Диагностика без LLM; `--save-dir artifacts` сохраняет медиа |
| `tests/` | Открытые тесты и фиксированные примеры результатов |
| `docs/` | Условие, контракты, документация и правила сдачи |
| `deploy/`, `Dockerfile`, `compose.yaml` | Готовое размещение на Linux-хосте |
| `SUBMISSION.md` | Форма сдачи; заполните её своими словами |

Эталонного решения и закрытых тестов в этом репозитории нет. [Памятка преподавателю](docs/instructor.md) содержит порядок подготовки курса, но не ответы.
