# Задание

## Результат

Создайте MCP-сервер на Python с двумя обязательными инструментами, подключите его к Алисе и запишите демонстрацию. Работайте индивидуально. Базовая часть рассчитана ориентировочно на 4–6 часов после настройки окружения; свободная — ещё на 2–4 часа. Даты и способ отправки преподаватель объявляет отдельно.

Вы научитесь читать описание протокола, задавать схемы аргументов, возвращать структурированные данные и изображения, обрабатывать ошибки и проверять сервер настоящим MCP-клиентом.

## Правила работы

Запрещено использовать LLM и генеративных помощников для написания или изменения кода, генерации тестов, отладки, объяснения документации, подготовки текста сдачи и сценария выступления. Отключите генеративное автодополнение в редакторе.

Разрешены официальная документация, обычный поиск без генеративных ответов, учебники, отладчик, обычное негенеративное автодополнение и консультации преподавателя. Небольшие заимствованные фрагменты из документации укажите в `SUBMISSION.md`; копировать готовое решение однокурсника нельзя.

**Исключение для Алисы:** она используется как тестируемый клиент для выполнения пользовательских задач через ваши инструменты. Можно наблюдать её вызовы и ответы. Нельзя просить её объяснять документацию, предлагать код, диагностировать реализацию или переписывать описания инструментов. Технические проблемы исследуйте через `client.py`, тесты и документацию.

На защите нужно уметь объяснить собственное решение и самостоятельно внести небольшую правку. Автоматические «детекторы AI-кода» не используются для оценки.

## Этап 1. Подготовка

1. Создайте свою копию репозитория.
2. Установите зафиксированные зависимости и запустите тесты `starter`.
3. Вызовите `echo` через `client.py`.
4. Прочитайте [документацию по маршруту](reading.md).

## Этап 2. Обязательные инструменты

В функции `register_tools` файла `tools.py` зарегистрируйте `inspect_unicode` и `render_identicon`. Их точные имена, входы, выходы, ограничения и алгоритмы описаны в [контрактах](contracts.md).

Можно организовать внутренние функции и классы по своему усмотрению. Для регистрации и формирования результатов используйте официальный MCP Python SDK. Не реализуйте JSON-RPC вручную.

Опишите назначение, параметры, ограничения и формат результата каждого инструмента. Описания должны позволять Алисе выбрать инструмент по пользовательской задаче.

Обязательные инструменты:

- работают без интернета, БД, LLM и истории запросов;
- не читают произвольные файлы пользователя;
- вычисляют результат из аргументов и не сохраняют его на сервере;
- одинаково работают независимо от порядка предыдущих вызовов;
- корректно отказывают на некорректном вводе и продолжают работать.

Файлы окружения и TLS-сертификаты инфраструктуры не считаются хранением пользовательской истории.

## Этап 3. Проверка

Запустите `python -m pytest`. Перед подключением к Алисе весь обязательный набор должен проходить. Исправлять или отключать выданные тесты, менять критерии CI ради зелёной проверки нельзя. Свои тесты добавлять можно и полезно.

Проверяющая система использует исходные тесты преподавателя, поэтому изменения в локальной копии проверок не влияют на оценку. Дополнительные случаи проверяют только опубликованный контракт. Таймауты тестов предназначены для обнаружения зависшего сервера; скорость модели Алисы в оценку не входит.

## Этап 4. Алиса и сдача

Получите внешний HTTPS-адрес по [инструкции](deployment.md), подключите сервер к [Алисе](alice.md), запишите видео и заполните [форму сдачи](submission.md). В базовом задании публичный endpoint не содержит ключей и не принимает приватные данные.

## Этап 5. Конкурс — по желанию

После прохождения обязательных тестов добавьте свою способность в `custom_tools.py`. Следуйте [правилам конкурса](contest.md). Дополнительные инструменты не должны изменять поведение обязательных.

## Оценивание: 100 баллов

| Часть | Баллы | Основание |
| --- | ---: | --- |
| `inspect_unicode` | 25 | Значения, нормализация, схема результата, границы |
| `render_identicon` | 25 | Алгоритм, PNG, размеры, схема аргументов, границы |
| Общая MCP-интеграция | 10 | Обнаружение, описания, ошибки и восстановление после ошибки |
| Документация и защита | 20 | Четыре ответа со ссылками и понимание собственного кода |
| Демонстрация через Алису | 20 | Два реальных вызова, аргументы, результаты и объяснение |

Баллы выставляются по группам требований, а не по числу параметризованных тестов. За обязательную часть можно получить все 100 баллов. Конкурс оценивается отдельно и не обязателен для максимальной оценки. Нарушения правил самостоятельности разбираются по правилам курса, а не выводятся из стиля кода.
