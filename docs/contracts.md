# Контракты обязательных инструментов

Версия задания: **1.0**. Среда: Python **3.12**, MCP Python SDK **2.3.0**. Спецификация MCP для чтения: редакция **2025-06-18**, раздел Tools; согласование версии протокола выполняет SDK.

Контракты описывают наблюдаемое поведение. Структура внутренних функций, классов и файлов не проверяется. Дополнительные инструменты и дополнительные поля JSON-результата разрешены, если не меняют обязательные поля.

## Общие требования

- Оба инструмента доступны через `tools/list` и `tools/call` на `/mcp` по Streamable HTTP.
- У каждого есть непустое осмысленное описание и JSON Schema аргументов.
- Схема содержит обязательные поля, типы, границы и допустимые значения, описанные ниже. Значения по умолчанию применяются, когда аргумент отсутствует.
- Все строки рассматриваются как последовательности Unicode-кодовых точек. Один видимый знак может состоять из нескольких кодовых точек. Одиночные суррогатные коды U+D800–U+DFFF вне области корректных входов задания.
- На корректный запрос возвращается успешный результат: `isError` отсутствует или равен `false`.
- Неверные аргументы не должны приводить к успешному результату или падению процесса. Допустимы результат инструмента с `isError: true` и непустым текстом либо MCP-ошибка Invalid params (`-32602`), в зависимости от слоя валидации SDK. Дословное сообщение не проверяется.
- Неизвестные дополнительные аргументы и политика приведения совместимых типов не оцениваются. Проверяемые неверные типы — явно несовместимые, например массив вместо строки и дробное число вместо целого.
- После ошибочного вызова следующий корректный работает.
- Проверки сравнивают смысл схем, а не точный JSON: использование `$ref` допустимо.

## 1. `inspect_unicode`

### Вход

| Поле | Тип | Ограничения | По умолчанию |
| --- | --- | --- | --- |
| `text` | string | Обязательно, 0–256 кодовых точек | Нет |
| `normalization` | string | Одно из `NFC`, `NFD`, `NFKC`, `NFKD` | `NFC` |

### Выход

Верните объект в `structuredContent` и объявите соответствующую `outputSchema`. Просто JSON-строки внутри текстового блока недостаточно. SDK может дополнительно создать текстовое представление; оно не проверяется на точное совпадение.

| Поле | Тип | Значение |
| --- | --- | --- |
| `length` | integer | Длина исходной строки в кодовых точках |
| `utf8_bytes` | integer | Размер UTF-8-представления исходной строки в байтах |
| `normalized` | string | Нормализация исходной строки выбранной формой |
| `characters` | array of objects | По одному объекту на кодовую точку исходной строки |

Объект символа содержит:

| Поле | Тип | Значение |
| --- | --- | --- |
| `index` | integer | Индекс с нуля в исходной строке |
| `character` | string | Исходный символ |
| `codepoint` | string | `U+` и шестнадцатеричное значение в верхнем регистре, минимум 4 цифры |
| `name` | string | Имя Unicode; если имени нет — `UNNAMED` |
| `category` | string | Двухбуквенная General Category Unicode |

Имена, категории и нормализация соответствуют `unicodedata` из Python 3.12. Не нужно определять язык, безопасность строки или визуальную похожесть символов.

### Примеры

Вход: `{"text":"Aа"}`. Вторая буква — **кириллическая маленькая а**.

```json
{
  "length": 2,
  "utf8_bytes": 3,
  "normalized": "Aа",
  "characters": [
    {"index": 0, "character": "A", "codepoint": "U+0041", "name": "LATIN CAPITAL LETTER A", "category": "Lu"},
    {"index": 1, "character": "а", "codepoint": "U+0430", "name": "CYRILLIC SMALL LETTER A", "category": "Ll"}
  ]
}
```

Другие случаи:

| Вход | Проверяемое поведение |
| --- | --- |
| Пустая строка | `length=0`, `utf8_bytes=0`, `normalized=""`, `characters=[]` |
| `e` + U+0301, NFC | `length=2`, `utf8_bytes=3`, `normalized="é"`; разбор по-прежнему исходных двух символов |
| `é`, NFD | Нормализованная строка состоит из `e` и U+0301 |
| `😀` | `length=1`, `utf8_bytes=4`, `codepoint="U+1F600"` |
| U+000A | `name="UNNAMED"`, `category="Cc"` |
| 257 символов | Ошибка |
| `normalization="BAD"` | Ошибка |

## 2. `render_identicon`

### Вход

| Поле | Тип | Ограничения | По умолчанию |
| --- | --- | --- | --- |
| `seed` | string | Обязательно, 1–256 кодовых точек | Нет |
| `cell_size` | integer | От 8 до 64 включительно | 32 |

### Алгоритм

1. Кодируйте `seed` в UTF-8 без удаления пробелов, изменения регистра или Unicode-нормализации.
2. Вычислите SHA-256. Получившиеся 32 байта обозначим `d[0]` … `d[31]`.
3. Цвет RGB: `(32 + d[0] % 192, 32 + d[1] % 192, 32 + d[2] % 192)`.
4. Для строки `y` от 0 до 4 и столбца `x` от 0 до 2 клетка активна, если `d[3 + 3*y + x]` нечётный.
5. Три клетки `[a, b, c]` образуют строку `[a, b, c, b, a]`. Получается сетка 5×5.
6. Добавьте со всех сторон белую рамку толщиной в одну клетку. Итог — сетка 7×7.
7. Каждая клетка — квадрат `cell_size × cell_size` пикселей. Активная клетка залита вычисленным цветом, остальные — RGB `(255, 255, 255)`.

Без сглаживания, текста, случайных чисел и дополнительных полей на картинке. Итоговый размер: `(7 * cell_size, 7 * cell_size)`.

### Выход

В `content` должен быть ровно один блок типа `image` с MIME-типом `image/png` и PNG-данными в base64. Дополнительные текстовые блоки допустимы. Ссылка на картинку, путь к файлу или base64 внутри обычного текста не заменяют image-блок.

Разрешены PNG в режимах RGB и RGBA; в RGBA все значения alpha должны быть 255. Сравниваются декодированные пиксели, а не сжатые байты PNG или метаданные файла.

### Граничные случаи

- Без `cell_size`: изображение 224×224.
- `cell_size=8`: 56×56; `cell_size=64`: 448×448.
- `seed=" "` допустим: пробел не удаляется.
- `é` и последовательность `e` + U+0301 хешируются как разные входы.
- Пустой `seed`, 257 символов, размеры 7, 65 и 8.5 дают ошибку.
- Повторный вызов с теми же аргументами даёт те же пиксели, даже если между вызовами были другие запросы.

Фиксированные примеры находятся в `tests/fixtures/identicons.json`. Они нужны для проверки реализации, а не для подстановки готовых ответов по известным строкам.
